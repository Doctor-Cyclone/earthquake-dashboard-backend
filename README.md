# Earthquake Dashboard — Backend

API землетрясений за последние сутки на Node.js и TypeScript. Получает публичную ленту USGS, проверяет события, кеширует результат и фильтрует его для фронтенда.

## Запуск

Требуется Node.js 24.11+ в ветке 24.x и npm. Откройте проект в WebStorm:

```sh
npm ci
npm run dev
```

`npm start` — запуск без наблюдения за файлами. Остановка: Ctrl+C.
По умолчанию сервер слушает `http://127.0.0.1:3000`.
Для изменения адреса скопируйте `.env.example` в `.env`, измените `HOST` / `PORT` и перезапустите сервер.
Порт — целое число от 1 до 65535. `.env` исключён из Git.
База данных и ключи API не требуются.

## Маршруты

| Запрос | Результат |
| --- | --- |
| `GET /health` | `200`, состояние HTTP-сервера (не доступность USGS) |
| `GET /api/earthquakes` | `200`, землетрясения за сутки |
| `HEAD` для этих маршрутов | Те же статусы и заголовки, без тела |
| Другие методы для этих маршрутов | `405`, `Allow: GET, HEAD` |
| Неизвестный путь | `404` |
| Некорректные параметры фильтров | `400`, `code: INVALID_QUERY` |
| Сбой USGS, когда успешного кеша ещё нет | `502`, `code: UPSTREAM_UNAVAILABLE` |

Ошибки возвращаются как `{ "error": "описание", "code": "код" }`; у `404` и `405` только поле `error`.

## Фильтры

Все параметры необязательны, границы включены:

| Параметр | Значение |
| --- | --- |
| `minMagnitude` | Минимальная магнитуда |
| `maxMagnitude` | Максимальная магнитуда |
| `minDepth` | Минимальная глубина, км |
| `maxDepth` | Максимальная глубина, км |

Пример: http://127.0.0.1:3000/api/earthquakes?minMagnitude=4.5&maxDepth=100

Принимаются конечные десятичные числа с точкой, например `4.5`, `0`, `-1.2`.
Пустые значения, повторы, неизвестные параметры, `NaN`, `Infinity`, экспоненциальная и шестнадцатеричная запись возвращают `400`.
Минимум не может превышать максимум. Отрицательные магнитуды и глубины допустимы.
При фильтрации по магнитуде события с неизвестной магнитудой исключаются.
Пустой результат — `200`, `count: 0`, `earthquakes: []`.

## Формат ответа

```json
{
  "source": "USGS",
  "period": "day",
  "generatedAt": "2026-10-04T12:00:00.000Z",
  "fetchedAt": "2026-10-04T12:00:02.000Z",
  "stale": false,
  "count": 1,
  "skippedCount": 0,
  "earthquakes": [{
    "id": "example",
    "magnitude": 4.5,
    "place": "Example location",
    "time": "2026-10-04T11:55:00.000Z",
    "longitude": 35,
    "latitude": 41,
    "depthKm": 100
  }]
}
```

Выше — иллюстративный пример, не реальное событие.

- `generatedAt` — время формирования ленты USGS, `fetchedAt` — последней успешной загрузки сервером. Оба в UTC ISO 8601.
- `stale` — истёк ли кеш, который пришлось вернуть после ошибки обновления. Это не оценка свежести измерений USGS.
- `count` — количество событий после фильтров.
- `skippedCount` — некорректные записи и события другого типа во всей исходной ленте, до фильтрации.
- События отсортированы от новых к старым. `magnitude` и `place` могут быть `null`.
- Координаты: longitude — долгота, latitude — широта. Глубина — в километрах.

## Кеш и сбои источника

Один кеш в памяти на экземпляр сервера, срок действия — 60 секунд от успешной загрузки.
Запрос после истечения срока запускает обновление; фонового опроса нет.
Одновременные запросы ждут одну общую загрузку USGS. Фильтры применяются к копии списка и не изменяют кеш.
Тайм-аут запроса USGS — 10 секунд.

При ошибке загрузки или неверном формате ленты успешный кеш сохраняется и возвращается с `stale: true` и прежним `fetchedAt`.
Повторная попытка выполняется по запросу не раньше чем через 60 секунд после ошибки.
Предельного срока хранения устаревшего результата нет: клиент должен показывать предупреждение и время загрузки. Во время длительного сбоя суточная лента относится к моменту последней успешной загрузки.
Если кеша нет, возвращается `502`; следующий запрос может повторить загрузку.
После перезапуска кеш пуст. `HEAD /api/earthquakes` использует тот же механизм.

## Структура и проверки

- `server.ts` — настройки и запуск.
- `app.ts` — HTTP-маршруты и ответы.
- `usgs.ts` — запрос источника.
- `earthquakes.ts` — проверка и преобразование записей.
- `cache.ts` — кеш и совместное обновление.
- `filters.ts` — параметры и фильтрация.

```sh
npm run check
npm test
npm run format:check
```

Тесты используют подставные ответы и управляемое время; сеть и ожидание минуты не нужны.
`npm run format` форматирует исходники и тесты.

## Подключение фронтенда

[Фронтенд](https://github.com/Doctor-Cyclone/earthquake-dashboard-frontend) использует Vite proxy `/api` к порту 3000. Оба проекта запускаются отдельно. Новые фильтры и отображение `stale` предстоит подключить на фронтенде.
Публичное развёртывание сервера в этот этап не входит; при размещении фронтенда и API на разных адресах потребуется настроить reverse proxy либо CORS под выбранный адрес.

[Описание формата USGS](https://earthquake.usgs.gov/earthquakes/feed/v1.0/geojson.php)

## Continuous integration

GitHub Actions запускает проверки при каждом push и pull request. Ручной запуск доступен во вкладке Actions → CI → Run workflow. Используется Node.js 24 и установка зависимостей из lock-файла через npm ci.

Проверки: форматирование, типы TypeScript и тесты. Отдельная сборка не нужна: сервер запускает TypeScript средствами Node.js.
